# Formal and Rust coverage

This matrix records what the Lean model proves, which Rust entry points have
regression coverage, and where the bridge compares them. `PROVED MODEL` means a
Lean theorem passed the kernel and the axiom audit. `TESTED RUST` means a bridge
run compared generated cases with a production Rust entry point. `UNESTABLISHED`
means the comparison is missing or has not passed. Rust regression commands below
identify separate tests. This lane ran the Lean audit only. It did not rerun Rust
tests or bridge families.

The model uses finite fuel. Exhaustion is an explicit outcome, not a proof of
termination. External command results and filesystem matches enter as observations.
The model does not prove parser correctness, kernel descriptor safety, terminal
behavior, process scheduling, or equivalence to the Rust implementation.

The audit discovers theorem declarations from the loaded environment in each
expected family namespace. It rejects a missing family, a family with no theorem,
an axiom declaration in a family, a transitive axiom outside `propext`,
`Quot.sound`, or `Classical.choice`, and a theorem link above that does not name an
audited declaration. Run it with `cd formal && lake env lean IshSemantics/Audit.lean`.
This direct invocation rereads the coverage document on each run; a cached Lake
module build can replay an earlier audit result.

The Rust PUA encoding is an internal conversion between raw shell bytes and text;
`ShellBytes` stores raw bytes. The Lean octet round-trip law proves its model map,
not every Rust string or OS conversion. The Lean kernel checks the model proofs.
The `aeneas` executable was unavailable on `PATH`, so this work does not claim
that Lean translates or refines the Rust code.
