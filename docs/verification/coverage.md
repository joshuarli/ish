# Formal and Rust coverage

`PROVED MODEL` identifies a theorem checked by Lean's kernel about the Lean
model. `TESTED RUST` identifies generated inputs compared with a production Rust
entry point. A passing bridge run is evidence for its bounded inputs and
assumptions. It does not prove that the model covers all Rust behavior or that
Rust refines the model. `PROVED EXTRACTED RUST` identifies a proof about a fresh
translation of a production Rust function, subject to the documented extractor
trust boundary. `TESTED BOUNDARY` identifies explicit protocol and
domain rejection checks outside the semantic case count.

The last combined run before placement cases were added passed 1,000 supported
semantic cases in each of six families, for 6,000 comparisons. Each family
rejected its comparator control. Protocol checks and explicit effects boundary
checks also passed. The bridge rejects `unsupported_domain` and `fuel_exhausted`
outcomes during semantic comparisons. Its effects boundary cases test those
outcomes separately. The current policy-only run passed 1,000 generated cases,
including placement cases, with a rejected comparator control. Run the combined
comparison with `cargo run --example semantic_bridge -p ish -- --family all --cases 1000`.
`make verify` also compiles and detects four [production mutations](mutation-testing.md).
The expansion [generation reference](expansion-generation.md) lists the seeded
315-combination schedule that follows the first 53 fixtures.

The model uses finite fuel. Fuel exhaustion is an explicit outcome, not a
termination proof. Evaluation and expansion receive observations for external
process behavior. The model cannot prove the observed behavior, parser
correctness outside generated inputs, kernel descriptor safety, terminal
behavior, or process scheduling.

The coverage audit discovers theorem declarations from each expected family. It
rejects a missing family, a family without a theorem, a family axiom, or a
transitive axiom outside `propext`, `Quot.sound`, or `Classical.choice`. It also
checks that every qualified theorem reference in this matrix names an audited
declaration. Run `cd formal && lake env lean IshSemantics/Audit.lean` to check
the document and theorem axioms.

The Lean octet round-trip law proves the model's byte map. It does not prove
every Rust string conversion or OS boundary. Production `ShellBytes` stores raw
bytes. The PUA encoding in `encoding.rs` carries raw bytes through Rust text
paths and escapes literal marker characters so decoding is reversible. It is an
implementation codec, separate from the Lean octet representation.

The bridge compares selected Rust behavior with the model. The separate
[shift-count refinement](refinement.md) proves the freshly extracted production
helper's domain decision and conversion for every `i64` input.
Its [shift_count_refines and shift_count_matches_model theorems](../../formal/Refinement/Shift.lean)
connect that result to both model shift branches for every 64-bit left operand.
`make verify-refinement` regenerates the translation and checks both theorems and
their transitive axioms. The extractor uses its own Rust nightly under `.work/`.
The proof trusts the extraction tools and does not cover production shift
primitives, parsing, other operators, or compiled machine code.
